## 1. The saved repairs verify

support failures. The core refit uses 2,186 events on 206 hosts and matches the
independent ablation: M2 s = 2.046959. Calibration draws are correctly labelled
calibration-only and carry the declared seed.

The development ledger contains 5,425 unique intended-event IDs and its status
counts reproduce the summary. Direct checking distinguishes 25 unmatched

latter are **insufficient coverage**, not necessarily zero cadences: the code

The Gaussian approximation for calibration and adapter representation for

## 2. Passing all/none scenarios does not bound partial selection

Injection grids were not exported. The shared rule therefore leaves 137
confirmation and 239 replication support decisions unknown. D059 evaluates
two scenarios: reject every unknown event, or accept every unknown event.
Both pass all eight criteria. That result reproduces, but it is a sensitivity
comparison, not a mathematical bound on the final rule's calibration.

Coverage, z-RMS, brightness regressions and their host bootstrap intervals are
not monotone as events or hosts enter. A partial subset can pass support while
the others fail. To demonstrate the logical gap, keep all certainly accepted
events and assign support success only to the unknown events whose truth falls
outside the reported 95% timing interval:

| Sample | Certain / unknown events | Diagnostic unknown subset accepted | Resulting hosts / events | Coverage | Coverage 90% interval |
|---|---|---:|---|---|---|
| Confirmation | 1,341 / 137 | 10 | 103 / 1,351 | 0.9241 | [0.9003, 0.9456] |
| Replication | 1,129 / 239 | 6 | 99 / 1,135 | 0.9222 | [0.8946, 0.9463] |

Both fail the fixed coverage lower-bound requirement 0.93. Replication also
fails other criteria. The counterexample uses truth to disprove the asserted
bound; **it is not a proposed selection rule, a claim about actual support,
or evidence that the actual amended pipeline fails.** No assumption in the
package rules out such dependence of support on timing error.

Consequently, retract “the evidence does not depend on the unexported support
outcomes.” Preserve the two passing scenarios, labelled as sensitivities.
My recommended repair is a targeted replay of the **same existing frozen
injection runs**, with their input identities/seeds and unchanged timing core,
exporting the missing grids/diagnostics. Apply the actual shared support gate
and rerun the eight fixed criteria. This is completion of an existing test,
not a further host replication. An explicitly reconciled Gaussian-only rule
would instead make the all-rejected scenario the actual rule, but requires its
own consistent refit/forecasts and declared narrower outcome scope; it is not
adopted by this review.

## 3. Finish the executable final path before hashing

The new acceptance module is used in `prefreeze_package`, `prefreeze_evidence`
and `prefreeze_attempts`. The scoring/measurement CLI does not call it. The
contract test manually changes rejected rows before calling the I1 adapter;
this proves a possible composition, not the final command's behavior. The
configured `evaluation_joint_bootstrap` seed is not consumed by any execution
path. The synthetic exercise correctly limits itself to scoring/refitting
directly constructed accepted event dictionaries.

Complete one executable final-analysis path that consumes the fixed manifest
and measurement/product diagnostics, retains exactly one terminal row per
intended event, applies the shared acceptance rule, scores through the declared
adapter representation and runs B = 2,000 joint host refits using the evaluation
seed. Persist host order, multiplicities, parameters, paired differences and
receipts. It can be implemented and tested entirely on synthetic/saved
development inputs before any protected access. Hash that code and contract
alongside the config, lists, parameters and forecasts.

Two specific fail-closed details belong in the same repair:

- `event_state` accepts a production Gaussian row lacking both `q025_s` and
  `q975_s`, because certification is checked only if a key exists. Require the
  actual Gaussian-certification diagnostics for production. Adapt injection
  ledger fields explicitly rather than implicitly accepting missing evidence.
- `prefreeze_attempts.development` currently appends unreadable products to
  `products_unenumerated` and continues. No such failure occurred in the saved
  development artifact, but that branch does not retain their intended events.
  The final path must start from the fixed manifest so absent/read-failed
  products keep their event rows without needing readable headers.

This does not reopen the model family, margins, threshold, weights or joint
bootstrap design. Once actual support-selection evidence and this final path
verify, the remaining task is the hash-bound freeze proposal and Barry's
separate decision on protected access. A focused check should suffice.
