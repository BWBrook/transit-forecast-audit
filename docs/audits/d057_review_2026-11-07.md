## 1. Shape-fit QC: a narrower repair

The controls contain 3,514 timed windows before a shape cut. Threshold 10
retains 3,435; threshold 100 retains all 3,514. Both retain the sole spurious
timing (shape reduced χ² 1.454) and all three matched timings with |z| > 5.
The independent gate audit also found that threshold 10 removes 41
confirmation injections, including the WASP-33 host; threshold 100 removes
none of the injections already retained under D056's integration rule.

The real demonstrated bad timing, WASP-54b S50, has shape reduced χ² 228.
Threshold 100 rejects it and the zero-yield WASP-92b S50 product. Threshold
10 additionally rejects three HD 63433 products. These observations favor
100 for the limited purpose of detecting gross shape-fit failure while
preserving the accepted calibration evidence. They do not establish an
optimal threshold or transfer accuracy. No additional threshold search is
requested. The proposed 100 is itself selected during development review,
not part of the original timing preregistration.

The shape statistic uses formal cadence errors, a common transit shape and
per-window baselines. It can respond to stellar variability, error-scale
mismatch and shape mismatch as well as identification failure. The inferential
target remains conditional on accepted light curves and successfully timed
events. Keep every rejected product in the intended-opportunity denominator.
The count one in 3,514 is an empirical result from dependent, deliberately
constructed controls, not a transferable false-identification probability.

The majority gate is not required as primary. Its losses of valid timings are
a useful cost diagnostic. Removal of a TOI-125 timing does not by itself prove
statistical bias in an untouched future comparison; either gate changes the
accepted-event population. Avoid describing either selection as neutral.

## 2. Acceptance must match the fitted candidate

`prefreeze_package.gated_rows` applies SPOC selection, shape rejection and two
integration flags. It never calls the adapter's endpoint-support check.
`sprint2_forecasts.our_events` then uses Gaussian timing SDs even for rows
marked `gauss_ok=False`. The declared final convention must explicitly say
which accepted likelihood representation is used for fitting and scoring;
the guarded adapter cannot be bypassed while the configuration claims it.

The saved-grid check finds eight retained timed events failing the existing
support check. Three enter the 2,189-event core training set:

- GJ1252b S67 D1247;
- GJ1252b S67 D1271;
- GJ1252b S67 D1277.

An independent refit excluding those three changes M2 s from 2.046778 to
2.046959. This supports numerical stability of the current point fit; it
does not excuse the contract mismatch. Full-support likelihood computation
can remain deferred only if the adopted rule consistently rejects unresolved
support and uses the same declared representation in calibration/evaluation.

Missing product matches, missing shape diagnostics and nonfinite statistics
must yield explicit unresolved/rejection states, rather than pass because
`NaN > threshold` is false. Use one acceptance function so that evidence,
attempt statuses, candidate fits and future measurement follow the same rule.
Regenerate the eight-criterion calibration evidence, parameters and forecasts
from that implementation before hashing. Independent reconstruction suggests
the omitted noise-ratio checks pass; the missing generator is a reproducibility
gap rather than evidence of a failed criterion.

## 3. Fixed attempts: preserve unknown observability

The manifest totals independently recount as 3,103 unique core events on 156
planets, 291 extension events on 28 planets, and five excluded events. This
accepts the explicitly restricted metadata subset, not exact time conversion
or exhaustive eligibility.

The development attempt function builds its manifest from available header
spans of products that reached the identification table. That is not yet the
sealed-era fixed-manifest execution path: unavailable/read-failed products
must also retain their intended events. Persist a row-level ledger with event
and product identities, terminal status and the basis for coverage assertions.

The claim that all 830 absent windows are cadence gaps is unverified.
`timing.windows` enumerates windows around the **recovered** train; the attempt
ledger looks up their nearest DRD cycles. An intended event with no associated
window can be unrecovered, phase-shifted or genuinely uncovered. The executable
synthetic counterexample has cadences at DRD epoch zero, but a recovered train
shifted by half a period has no windows. `build_ledger` reports a gap anyway.

Keep all intended events in the overall recovery denominator. Distinguish
`unmatched_expected_event`/unknown observability from a directly established
cadence gap. Any coverage-conditioned denominator needs its own declared
window and cadence/quality check; absence from a recovered train supplies
neither. The total 5,425 may remain a useful development metadata denominator,
but its current gap labels cannot support the reported interpretation.

## 4. Joint inference: sound design, incomplete persistence/path check

The joint host bootstrap correctly retains shared host identities and applies
the same multiplicities to training and evaluation. Preserve it as primary;
the fixed-parameter interval remains a conditional result. There are 270 hosts
in the exercise union: 206 training, 156 evaluation and 92 shared.

The stored 400 candidate draws contain only the 206 calibration hosts because
the call is `joint_draws(train, [], ...)`. They are training-only draws, not
the exercise's joint draws. The exercise creates joint multiplicities and
parameters in memory, then writes only aggregate intervals while asserting
`multiplicities_and_parameters_stored: true`. Persist the actual joint host
order, multiplicities, parameter draws and paired score differences, or remove
that assertion. Actual final-evaluation draws will necessarily be generated
after access and should have the same persistence contract.

The synthetic exercise directly manufactures accepted event dictionaries. It
checks forecast variance, predictive scoring, refitting and aggregation;
it does not exercise identification, fixed attempts, gates, outcome conversion
or event mapping. Retain it with that narrower label. Add one small synthetic
contract check using the actual acceptance/mapping/adapter path, including a
support failure, missing diagnostic, unmatched event and stored joint draw.
No full light-curve simulation, new host sample or power study is requested.
